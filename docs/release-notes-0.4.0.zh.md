# Birdview 0.4.0 — 架构评审、技能兼容性体检与更改路径

[English](release-notes-0.4.0.md)

这个版本让你更容易回答三个问题：**架构该怎么改？多个技能会不会同时误触发？一次改动还会影响谁？** 在原有架构与约束视图之上，Birdview 新增架构评审、技能触发兼容性体检，并改进更改视图。

## 架构评审：先看懂建议，再决定怎么改

评审先读取源码，再把现状、问题与建议画出来：

- **现状图与红笔批注**：展示已有模块、调用关系和具体问题，附源码原文。
- **建议稿**：展示调整后的边界、调用方职责变化、收益、迁移成本和验证步骤。
- **可核对的依据**：使用 `--repo` 渲染时，引用会与指定提交或工作区源码逐行核对；未提供仓库时标记为未核对。引用匹配不等于建议正确。
- **先审后改**：展示页面后等待你确认具体方案，再实施已授权的范围。

安装独立入口后，在 Codex 中使用：

```text
$birdview-review 评审这个项目的架构，画出现状、问题和优化建议，先不修改代码。
```

Claude Code 使用 `/birdview-review`。也可以明确要求 Birdview“优化架构”或“评审模块边界”；自然语言触发取决于宿主发现并选择技能，不是固定关键词拦截器。查看[评审示例](../examples/review.html)和[评审流程](../references/review-architecture.zh.md)。示例基于标注的源码版本，不代表对当前版本的最新评审。

## 技能兼容性体检：检查哪些请求会让技能撞车

体检先收集安装信息，再由 AI 阅读技能正文，比较触发范围、调用模式、写入权限和确认要求。结论围绕具体场景说明：**可以一起用、需要先后顺序、可能冲突、仍无法判断**，并附双方证据与建议。

```text
$birdview-compatibility 检查本地技能的触发是否冲突，用中文说明冲突场景、依据和建议。
```

Claude Code 使用 `/birdview-compatibility`。结果是便于阅读的文字／Markdown 报告，同时保留 JSON；报告语言跟随对话，CLI 调用须显式传入 `--language zh` 或 `en`。单纯扫描到重复名称或宽泛描述不等于确认冲突，安装清单也不是最终结论。体检不会自动禁用、重排或改写其他技能。

## 更改视图：看清本次路径与范围外影响

- 在同一张架构图上查看 Agent 声明的改动模块、文件和执行步骤。
- 打开「范围外影响」，查看与计划直接相连、但未列入改动范围的模块，帮助发现需要进一步核对的边界。
- 改进连线路由、短折线和屏幕适配，在桌面与窄屏下更容易追踪路径。

这层影响来自图中已声明的直接关系，不表示这些模块必须修改，也不证明传递影响已被完整分析。查看[架构与更改示例](../examples/harness-activity.html)，其中活动为模拟数据。

## 其他改进与升级提醒

- `birdview deliver` 串联输入校验、按需约束编译与历史收集、页面渲染和交付回执，减少手工执行这些步骤；它不会替 AI 判断规则含义，也不代表视觉验收通过。
- 约束来源在约束页的「按目录」中阅读。独立 `.sources.html` 导出、`--sources` 参数和 `sourceHref` 接口已移除；依赖旧入口的脚本或链接需要更新。
- 旧的并排对照入口由更改路径与「范围外影响」取代。架构、约束和评审导航按实际渲染的数据提供。
- 默认仍为按需触发，自动模式可选。绘图后确认方案的流程继续保留。

## 安装与更新

按[安装指南](installation.zh.md)更新完整 `birdview` 技能包，保留本地定制。固定到本版时使用 v0.4.0 发布后的源码归档；`npx skills add Qiuner/birdview --skill birdview` 安装的是仓库当前版本。

独立命令需要对应入口：将包内 `review-skill/` 安装为同一技能目录中的 `birdview-review/`，将 `compatibility-audit/` 安装为 `birdview-compatibility/`，并保留完整的相邻 `birdview/` 包。只安装主技能不会自动安装这两个入口。

在主技能目录运行 `npm ci` 和 `node scripts/birdview.mjs doctor`，对已配置项目重新运行 `setup --project <project-root>`，刷新基础规则并保留已有模式。新建 Agent 任务验证技能发现和触发。需要 Node.js 18 或更高版本；分发含生成后的 JavaScript，无需自行编译 TypeScript。通过 GitHub 分发，npm 包仍为私有。

## 验证与边界

发布候选需要通过 `npm run check:pr`：类型、生成产物、单元测试、浏览器交互、示例重新生成、输入校验和双语文档检查。提交后、打标签前，还需运行 `npm run check:install` 验证源码归档安装；具体发布状态以[发布检查清单](releasing.zh.md)和候选提交的检查结果为准。

Birdview 展示 AI 整理的快照、证据和声明，不独立监控所有编辑，也不提供文件系统写入锁。技能兼容性结论需要结合宿主规则和实际任务，不是安全认证。约束页需要已审查的约束数据，仓库暂未提供可直接打开的约束示例。
